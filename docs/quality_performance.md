# 품질실적

`/quality/performance`에서 보고 월과 자료 구분을 선택해 원본 양식으로 실적을 조회합니다. 기본 보고 월은 전월입니다. 외부 연동과 MES 입력은 각각 조회하며 두 원장을 무조건 합산하지 않습니다.

## 시트 구성

사용자 요청으로 **시트 6(매출·클레임)을 화면과 다운로드 Excel에서 삭제**했습니다. 현재 보고서는 16개 시트와 27개 차트입니다. 목차에서도 해당 항목을 제거했습니다. 업로드된 원본 `assets/QualityPerformance_Template.xlsx` 자체는 보존합니다.

원본 XML에서 셀 병합·행높이·열너비·글꼴·테두리·그림 위치를 읽어 HTML 양식을 생성합니다. 생성기는 `scripts/build_quality_form.py`, 양식 정의는 `static/quality_performance_form.json`입니다. 화면은 `/api/quality/performance/form`을 호출하며 Excel 출력과 같은 `build_excel` 결과의 셀 값·숫자 서식·차트 데이터를 사용합니다.

Excel은 openpyxl로 다시 저장하지 않고 ZIP 안의 값·수식 캐시·차트 캐시를 갱신합니다. 시트 6과 그 시트에만 소속된 그림·차트·인쇄 설정을 제거하며, 남은 시트의 스타일·병합·그림·인쇄 설정은 유지합니다. 삭제된 시트에 대한 요약 수식은 이미 계산된 값으로 보존해 끊어진 참조가 생기지 않도록 합니다. 기존 수기 저장 자료나 감사 이력은 삭제하지 않습니다.

## 집계 기준

- 원자재 불량은 사용자 지정에 따라 0입니다. CAP은 280089/280098/280144, YR280554/555/556/589, SEAL은 480187/480207이고 동소재는 원본 자재유형 ‘동소재’입니다.
- 공정 TOTAL 생산수량은 복합선반·탭핑·조립을 합산합니다. 조립 불량수량 칸은 월별·연간 모두 비우고, 공정 불량 합계에서는 제외하여 최종검사에만 집계합니다.
- 생산수량은 양품+불량+셋업이며, 불량 분자는 불량수량입니다. 셋업을 임의로 불량 유형에 넣지 않습니다.
- 최종검사 SV1·AX1-EV는 내부 품명으로 구분합니다. 310061/310067/310070 묶음과 310140은 품번과 BOM 상위 연결로 구분합니다. 품목군이 미연결인 조립실적도 조립 생산수량 행에는 보이고, 최종검사 분류 누락은 확인사항에 표시합니다.
- 공유 조립 불량 유형은 묶음당 한 번 합산합니다. 유형 미분류·합계 불일치는 기타와 확인사항으로 표시합니다.
- 외주는 메인텍·혜성금속에 연결된 외부 검사 확정일 또는 MES 입고일의 자료를 사용합니다. 3-1의 생산수량은 실제 입고수량이고, 불량수량은 업체별 얼룩·박리 합계입니다. 내부 거래처 ID 및 외부 입고번호·품번으로 업체를 우선 연결하고, 연결 정보가 없으면 법인 표기·공백을 정규화한 업체명을 대조합니다. 검사/불량이 없는 입고도 생산수량에 포함하며, 입고원장이 없는 구자료는 불량현황의 입고수량을 사용하고 확인사항을 표시합니다. 3-2 유형별 표에는 얼룩·박리만 합산합니다. 3-2 유형 합계와 3-1 업체별 불량 합계를 일치시키고 3시트에 종합합니다. 찍힘·긁힘·치수·기타 등 나머지 보고서 유형은 0입니다. 원본 불량 기록은 수정하지 않습니다. 업체·입고수량·얼룩/박리 유형 미연결 및 원본 유형 합계 불일치는 확인사항입니다.
- 2024·2025 비교 실적은 제공된 원본 파일의 참고값으로 출처를 표시합니다. 다른 보고 연도의 확인되지 않은 비교값은 재사용하지 않습니다.
- 납품수량은 선택한 자료 구분의 실제 확정 출고 상세에서 자동 합산합니다. 외부는 present인 OUT_FIN 전표의 품번별 TR_QTY, 내부는 CONFIRMED 출고의 ShipmentItem.shipped_qty를 사용합니다. 원 LOT 전체수량이나 박스별 수량을 재합산하지 않습니다. 취소·누락·중복 상세·다른 기간 자료는 제외하며 내부와 외부를 중복 합산하지 않습니다. 자료가 없으면 0과 확인사항을 표시합니다.
- 원본 양식 밖의 고객불량 입력 영역에서 보고 월의 불량수량과 발생건수를 직접 입력·저장합니다. 미입력은 빈칸이며 실제 0과 구분합니다. 납품수량은 수정할 수 없고, 기존에 수기로 저장한 납품수량도 자동 집계 값을 덮지 않습니다. 조회 월 이후 실적은 공란입니다.
- 고객불량 입력은 기존 월별 저장·버전 충돌 검사·수정 이력을 사용합니다. 저장 전 월/자료 구분 변경에는 확인을 받고 엑셀 다운로드는 저장 후 가능합니다. 조회 전용 계정은 입력/저장할 수 없습니다. 기존 작성자·비고·삭제된 시트의 수기 기록은 보존합니다.

원본에서 고정 숫자를 쓰던 차트 3개는 실제 셀 범위로 연결하고, 요약 차트의 잘못된 항목 이름을 해당 지표 셀에 연결했습니다. 사용자가 정한 목표와 원본의 달성률 `2−실적/목표` 방식은 유지합니다.

조회는 생산·재고·입고·출고 원장을 변경하지 않습니다. 수기 저장 모델은 독립 `quality_performance_months`, `quality_performance_audits`이며 기존 값과 이력을 보존합니다.

## 접속 주소와 실행 환경

API는 특정 IP에 고정하지 않고 **현재 접속 주소 기준의 상대 경로**를 사용합니다.

| 화면 접속 | 조회 API |
| --- | --- |
| `http://localhost:8000/quality/performance` | `http://localhost:8000/api/quality/performance/form` |
| `https://129.225.172.135/quality/performance` | `https://129.225.172.135/api/quality/performance/form` |

로컬과 서버는 각각 실행 중인 앱의 DB를 사용합니다. 서버 IP로 로컬 API를 우회시키지 않습니다. 로컬 배치 파일은 배치 파일이 있는 프로젝트 폴더로 이동한 뒤 현재 터미널의 `python`으로 실행합니다. 별도 가상환경 선택·강제 폴링 설정을 덧붙이지 않습니다. 직접 실행하는 기존 명령 `python -m uvicorn app:app --host 0.0.0.0 --port 8000 --reload`도 유지합니다.

`run_server.bat`는 기존 8000번 리스너가 있으면 PID와 오류를 표시하고 시작을 중단합니다. 이미 실행 중인 서버를 자동 종료하지 않습니다. HTTPS 전환한 Oracle 서버는 `docker-compose.oracle-https.yml`로 앱과 프록시를 재빌드합니다. HTTP 전용 구성이 필요한 경우에만 기존 `docker-compose.oracle.yml`을 사용합니다. 기본 서버 DB는 `/data/manual_labels.db`이며 환경 변수로 변경할 수 있습니다.

`app.py`의 일반 품질관리 라우터 구역에서 품질실적 화면과 API를 등록합니다. 원인을 찾는 동안 추가했던 API 시작 검사·진단 로그·공통 안내 템플릿 우회 처리는 제거했습니다.

로컬 404의 실제 원인은 기존 서버의 부모 프로세스가 종료된 뒤에도 자식 Python 서버가 소켓을 유지하며 이전 코드로 응답한 것이었습니다. 남은 자식 프로세스를 종료하고 서버 하나를 실행한 뒤 사용자가 정상 조회를 확인했습니다. 실행 중인 서버를 하나만 유지하며, 배치 파일의 포트 검사는 중복 실행 예방용으로 남깁니다.

## 검증

임시 DB와 별도의 앱 복사본에서 품질실적 관련 테스트 48개를 확인합니다. 실제 브라우저에서 월별 고객불량 저장/재조회, 0/빈칸 구분, 저장 충돌 시 입력 유지, 조회 전용 차단과 엑셀 다운로드도 확인합니다. 수량·불량률·원본 서식·수기 공란·자료 구분 분리·삭제 시트 참조·패키지 관계·계산 체인·실제 앱 9월 API 및 Excel 다운로드를 검증합니다. 사용자 PC 운영 수치 대사와 Windows 배치 실행은 이 환경에서 직접 검증할 수 없습니다.

3-1 업체 연결은 품번이 `-Ag`로 끝나면 품번 규칙을 우선합니다. `310060-Ag`, `310140-Ag`는 메인텍, 나머지 `-Ag` 품번은 혜성금속입니다. 입고수량과 불량수량에 동일하게 적용하며, 영문 대소문자는 구분하지 않습니다. 다른 품번은 기존 업체 연결을 유지합니다.

1~5시트의 문제점·원인 및 대책·개선방향은 수기 품질 분석 내용만 표시합니다. 시스템 집계 오류·미연결 안내는 보고서 본문에 덧붙이지 않고 화면 하단 집계 확인사항에 표시합니다.
