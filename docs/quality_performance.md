# 품질실적

`/quality/performance`에서 보고 월과 자료 구분을 선택해 원본 양식으로 실적을 조회합니다. 기본 보고 월은 전월입니다. 외부 연동과 MES 입력은 각각 조회하며 두 원장을 무조건 합산하지 않습니다.

## 시트 구성

사용자 요청으로 **시트 6(매출·클레임)을 화면과 다운로드 Excel에서 삭제**했습니다. 현재 보고서는 16개 시트와 27개 차트입니다. 목차에서도 해당 항목을 제거했습니다. 업로드된 원본 `assets/QualityPerformance_Template.xlsx` 자체는 보존합니다.

원본 XML에서 셀 병합·행높이·열너비·글꼴·테두리·그림 위치를 읽어 HTML 양식을 생성합니다. 생성기는 `scripts/build_quality_form.py`, 양식 정의는 `static/quality_performance_form.json`입니다. 화면은 `/api/quality/performance/form`을 호출하며 Excel 출력과 같은 `build_excel` 결과의 셀 값·숫자 서식·차트 데이터를 사용합니다.

Excel은 openpyxl로 다시 저장하지 않고 ZIP 안의 값·수식 캐시·차트 캐시를 갱신합니다. 시트 6과 그 시트에만 소속된 그림·차트·인쇄 설정을 제거하며, 남은 시트의 스타일·병합·그림·인쇄 설정은 유지합니다. 삭제된 시트에 대한 요약 수식은 이미 계산된 값으로 보존해 끊어진 참조가 생기지 않도록 합니다. 기존 수기 저장 자료나 감사 이력은 삭제하지 않습니다.

## 집계 기준

- 원자재 불량은 사용자 지정에 따라 0입니다. CAP은 280098, YR280554/555/556/589, SEAL은 480187/480207이고 동소재는 원본 자재유형 ‘동소재’입니다.
- 공정 TOTAL은 복합선반·탭핑만 집계합니다. 조립 행에는 실제 생산수량·불량수량을 참고용으로 표시하고 TOTAL에서는 제외합니다. 조립 불량은 최종검사에 집계합니다.
- 생산수량은 양품+불량+셋업이며, 불량 분자는 불량수량입니다. 셋업을 임의로 불량 유형에 넣지 않습니다.
- 최종검사 SV1·AX1-EV는 내부 품명으로 구분합니다. 310061/310067/310070 묶음과 310140은 품번과 BOM 상위 연결로 구분합니다. 품목군이 미연결인 조립실적도 조립 참고 행에는 보이고, 최종검사 분류 누락은 확인사항에 표시합니다.
- 공유 조립 불량 유형은 묶음당 한 번 합산합니다. 유형 미분류·합계 불일치는 기타와 확인사항으로 표시합니다.
- 외주는 메인텍·혜성금속에 연결된 외부 검사 확정일 또는 MES 입고일의 자료를 사용합니다. 업체·수량·유형 미연결은 확인사항입니다.
- 2024·2025 비교 실적은 제공된 원본 파일의 참고값으로 출처를 표시합니다. 다른 보고 연도의 확인되지 않은 비교값은 재사용하지 않습니다.
- 미입력 납품·고객불량 값은 공란이며 실제 0과 구분합니다. 새 양식에 수기 입력 UI는 아직 연결하지 않았습니다. 조회 월 이후 실적은 공란입니다.

원본에서 고정 숫자를 쓰던 차트 3개는 실제 셀 범위로 연결하고, 요약 차트의 잘못된 항목 이름을 해당 지표 셀에 연결했습니다. 사용자가 정한 목표와 원본의 달성률 `2−실적/목표` 방식은 유지합니다.

조회는 생산·재고·입고·출고 원장을 변경하지 않습니다. 수기 저장 모델은 독립 `quality_performance_months`, `quality_performance_audits`이며 기존 값과 이력을 보존합니다.

## 접속 주소와 실행 환경

API는 특정 IP에 고정하지 않고 **현재 접속 주소 기준의 상대 경로**를 사용합니다.

| 화면 접속 | 조회 API |
| --- | --- |
| `http://localhost:8000/quality/performance` | `http://localhost:8000/api/quality/performance/form` |
| `http://129.225.172.135/quality/performance` | `http://129.225.172.135/api/quality/performance/form` |

로컬과 서버는 각각 실행 중인 앱의 DB를 사용합니다. 서버 IP로 로컬 API를 우회시키지 않습니다. 로컬 배치 파일은 프로젝트 `.venv`를 우선 사용하고 앱·감시 폴더를 배치 파일의 프로젝트로 지정합니다. 공유 폴더에서도 변경을 감지하도록 파일 폴링을 사용합니다.

`run_server.bat`는 기존 8000번 리스너가 있으면 PID와 오류를 표시하고 시작을 중단합니다. 이미 실행 중인 서버를 자동 종료하지 않습니다. Oracle 서버는 `docker-compose.oracle.yml`의 `80:8080` 포트 매핑과 Docker 이미지 안의 앱을 사용합니다. 기본 서버 DB는 `/data/manual_labels.db`이며 환경 변수로 변경할 수 있습니다.

`app.py`에서 품질실적 라우터를 직접 등록합니다. 시작 시 API 등록을 확인하고 `MES runtime: PID=... APP=... quality API=/api/quality/performance/form`을 로그에 남깁니다. API가 없으면 시작을 실패시킵니다. 따라서 최신 정적 화면 파일이 보이는 것만으로 Python 서버 코드까지 갱신됐다고 판단하지 않습니다. 사용자 PC의 실제 404 해결 여부는 해당 실행 프로세스와 로그로 확인해야 합니다.

## 검증

임시 DB와 별도의 앱 복사본에서 관련 테스트 28개를 확인합니다. 수량·불량률·원본 서식·수기 공란·자료 구분 분리·삭제 시트 참조·패키지 관계·계산 체인·실제 앱 9월 API 및 Excel 다운로드를 검증합니다. 사용자 PC 운영 수치 대사와 Windows 배치 실행은 이 환경에서 직접 검증할 수 없습니다.
