# 발주 조회·입고 조회 및 기존 테스트 정리

작성일: 2026-10-07

## 화면 변경

별도의 '구매 조회' 메뉴를 만들지 않는다. 대상은 구매관리의 발주 조회·입고 조회와 발주 입력·구매 입력 화면에서 번호로 문서를 찾는 팝업이다.

- 일반구매 발주·입고 API에 offset/limit을 적용하고 전체 검색 건수를 반환한다.
- 외주 입고 API도 전체 건수와 일정한 정렬 순서로 페이지를 반환한다. 외주 발주 API의 기존 페이지 처리와 함께 사용한다.
- 조회 화면과 번호 조회 팝업은 500행씩 다음 페이지를 요청한다. 이전의 일반구매 2,000행·외주 발주 500행·외주 입고 1,000건 제한으로 뒤의 문서가 표시되지 않던 문제를 해결한다. 화면에는 기존처럼 검색 결과를 한 목록으로 표시한다.
- 일반구매 입고 상태는 전체/임시저장/입고확정 조건을 실제로 적용한다. 전체에는 임시저장도 포함한다. 과거 상태가 공란인 입고는 입고확정으로 표시·검색한다.
- 창고와 저장위치는 조회 화면에서 명칭을 표시한다. API의 기존 코드 필드는 유지하고 명칭 필드를 추가한다.
- 시작일이 종료일보다 늦으면 일반구매·외주가공 조회 모두 같은 오류를 반환한다.
- 연속 검색 시 늦게 도착한 이전 검색 결과가 최신 조건의 결과를 덮어쓰지 않도록 한다.
- 페이지 요청은 공통 서버 오류·로그인 만료 응답 처리를 사용한다.

## 기존 테스트와 현재 API의 불일치

- 도면 테스트: 테스트 요청과 동일한 분리 DB에 세션을 발급하고 커밋한 후 쿠키를 설정한다. 전역 DB에서 테스트 사용자 세션을 발급하던 호출을 모두 교체한다.
- 구매 테스트: 활성 창고·저장위치 마스터를 준비하고 요청에 필수 저장위치를 지정한다. 잘못된 값은 덮어쓰지 않아 기존 입력 검증 사례를 유지한다.
- 실제 앱의 LR LOT 생성 정책을 구매 테스트에도 적용한다. 앱을 가져오지 않고 pytest monkeypatch를 사용하므로 다른 테스트에 해당 정책을 영구 적용하지 않는다.
- 구형 LOT-IN 기대값을 현재 LR 형식으로 바꾸고, 발주수량 초과입고를 허용하던 기대값을 현재의 422 거절과 수량·입고 데이터 유지 조건으로 변경한다.
- 페이지 간 행 중복 방지, 상태 필터, 공란 상태 처리, 잘못된 검색조건, 필수 저장위치 누락을 검증하는 회귀 테스트를 추가한다.

사용자 요청에 따라 애플리케이션, DB, pytest와 브라우저 기능 테스트는 실행하지 않는다. 문법과 소스 연결만 점검한다. 과거 16개 통과·12개 실패·15개 오류 수치는 재실행 결과가 아니므로 새 결과로 갱신하지 않는다.

Python 라우터 변경이 포함되어 있어 MAIN 반영 후 앱 재시작이 필요하다. DB와 업로드 파일은 변경하지 않는다.
