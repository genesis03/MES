# 공정흐름도 운영 안내

## 하나의 기준 문서

- 표준문서 관리 → 공정흐름도가 품목별 공정번호·공정명·순서를 관리하는 단일 메뉴입니다. 별도의 '공정흐름' 메뉴/DB를 만들지 않습니다.
- 번호와 명칭은 같은 화면 셀 안의 두 입력란에 직접 입력하고 순서를 위로/아래로 조정합니다. 번호를 숫자로 제한하거나 생산 공정코드를 임의로 변환하지 않습니다.
- 기존 생산 공정마스터와는 역할이 다릅니다. 자재 입고·검사·보관 등 품목별 문서 단계도 포함하므로 생산마스터를 재작성하거나 덮어쓰지 않습니다.
- 입력 순서로 같은 화면에 직선형 공정흐름도를 표시하고 인쇄합니다. 분기/합류 도형 편집기는 이번 범위에 없습니다.
- 품목은 기존 item_master의 item_id로 연결하며 품번은 표시값입니다. 회사·번호·공정 이름 등의 예시값은 기본 등록하지 않습니다.

## 개정과 연결

- process_flow_revisions: 품목·개정번호·순서·버전·상태·이전 개정·개정 사유·등록/적용/폐기 정보·품목 스냅샷.
- process_flow_step_keys: 품목별 단계의 영구 연결 ID. 개정 시 해당 단계를 복사하면서 유지합니다.
- process_flow_steps: 각 개정의 번호·명칭·표시 순서·비고·행 제외 이력.
- 새 초안 저장만으로 현재 사용은 바뀌지 않습니다. 확인 후 현재 사용 적용 시 이전 현재 사용은 구버전으로 전환합니다. 품목당 현재 사용은 최대 1개입니다.
- 적용 문서는 직접 수정하지 않습니다. 개정 등록으로 새 초안을 만들며 모든 이전 문서와 제외 행을 보존합니다.
- FMEA는 같은 품목의 적용된 공정흐름도 개정과 해당 단계 ID를 선택합니다. 같은 공정의 고장 형태는 여러 분석행으로 작성할 수 있습니다.
- 새 FMEA 적용은 현재 사용 공정흐름도의 모든 단계에 분석행이 있어야 합니다. 공정번호·명칭·순서를 별도로 중복 입력하지 않습니다.
- 공정흐름도 개정은 이전 FMEA를 자동 변경하지 않습니다. FMEA 초안에서 새 흐름도 선택 시 같은 영구 단계 ID만 다시 연결하며 삭제/신규 단계는 사용자가 검토합니다.
- CP 관리계획서는 아직 개발 예정입니다. 향후 같은 흐름도 개정·단계 ID를 참조하도록 연결할 기반만 마련했습니다.
- 등록 문서/폐기 이력이 있는 품목은 물리 삭제를 차단합니다.
- READ 조회/인쇄, WRITE 등록/수정/적용/개정/폐기. 일반 사용자에게 새 권한을 자동 부여하지 않습니다.

## 업데이트 순서와 백업

1. 실제 로컬 DB와 도면 파일 보관 위치를 백업합니다. SQLite 실행 중 단순 파일 복사보다 서버 중지 후 복사 또는 SQLite 온라인 백업 방식을 사용합니다.
2. 사용자가 main을 git pull하고 서버를 재시작합니다. 기존 create_all과 추가 컬럼 마이그레이션으로 새 테이블 및 FMEA 연결 컬럼을 생성합니다.
3. 공정흐름도 초안→저장→적용, FMEA 연결→저장→적용, 개정 비교/인쇄 및 도면 개정 목록을 확인합니다.
4. 로컬 확인 후 Oracle 배포를 한 번에 진행합니다. 운영 DB /home/ubuntu/MES/data/manual_labels.db와 서버 영구 문서 저장소를 함께 백업합니다.
5. 운영 DATABASE_URL 및 문서 저장소 설정을 유지하고 코드만 갱신합니다. GitHub manual_labels.db를 Oracle 운영 DB로 복사하거나 덮어쓰지 않습니다.

- 기존 FMEA 내용/점수/날짜/공정 참조에는 자동 백필이나 추정 연결을 하지 않습니다. 구버전 diff_tracking은 false로 남깁니다.
- Oracle Cloud는 서버 위치이며 이 프로젝트의 운영 DB는 SQLite입니다. 이번 마이그레이션은 SQLite/PostgreSQL만 지원합니다.
- 요청에 따라 실행 테스트/브라우저 점검은 수행하지 않았습니다. 이 커밋 반영 자체는 Oracle 배포가 아닙니다.
