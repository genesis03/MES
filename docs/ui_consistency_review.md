# 메뉴·조회·UI 1차 점검 및 통일

## 작업 방식

- 최신 DB와 업로드 원본은 내부 PC에 있습니다. 이 작업에서 DB나 업로드 파일을 수정하지 않습니다.
- 실행·저장·브라우저 테스트는 사용자가 내부 PC에서 진행합니다. 아래 점검은 소스 문법과 파일 연결의 정적 확인입니다.
- 현장 문서보기·도면보기는 보류합니다. 예정 연결은 가공/조립 실적 등록, 입고 성적서, 공정순회 검사, 출하 성적서, 포장 처리입니다.

## 먼저 MAIN에 반영한 메뉴

- 작업표준서·검사기준서·포장사양서의 사이드바 이름에서 ‘관리’를 삭제했습니다.
- 외관검사 기준서(`/standard-documents/appearance-standards`)를 추가했습니다. 이후 사용자 요청으로 사이드바의 단독 메뉴를 제거하고 검사기준서의 최종검사 기준서 뒤에 유형 버튼을 배치했습니다. 버튼을 누르면 공통 유형 버튼 아래에 준비 중 안내가 표시됩니다. 기존 준비 중 템플릿을 사용하고 등록·저장 API나 DB 테이블은 만들지 않습니다.
- 대상은 완제품·반제품·원재료입니다. 일반 계정에는 기존과 동일한 메뉴별 접근 권한을 적용하며 새 권한은 관리자 계정 설정에서 부여합니다.

## 확인한 문제와 수정

| 확인한 차이 또는 문제 | 수정 |
|---|---|
| 새 메뉴와 검사기준서 세부 페이지가 고정 사이드바 선택표에 빠질 수 있음 | 실제 링크와 하위 권한 경로의 가장 긴 일치 항목을 선택. 기존 별칭도 유지 |
| 관리계획서만 개정번호에 `REV.`를 직접 입력하고 브라우저 prompt로 개정 | 공통 숫자 입력과 개정 대화상자 사용. DB에는 기존 `REV.n` 형식 유지 |
| 관리계획서 개정·공정 선택 목록에 영문 상태 표시 | 초안·현재 사용·구버전으로 표시 |
| 검사기준서 상태와 주요 버튼 명칭이 다른 문서와 다름 | 초안·현재 사용·구버전, 초안 저장·신규 등록·개정 등록·현재 사용 적용으로 맞춤 |
| 검사기준서 품번 조회에 Enter/초기화/선택 버튼 없음 | 조회 폼, 초기화, 키보드로 누를 수 있는 선택 버튼 추가. 기존 행 클릭 유지 |
| 검사기준서에서 먼저 보낸 조회 응답이 나중 조회 결과를 덮을 수 있음 | 요청 순번과 검사구분을 확인해 오래된 응답 제외 |
| 관리계획서 품번 조회에 초기화 없음 | 초기화 버튼 추가 |
| 문서별 조회·주요 버튼 높이가 34/36px로 다름 | 공통 36px, 13px 글꼴 적용. 회사 양식과 분석표 입력칸 크기는 유지 |
| 로그인 화면/HTML 응답이 JSON 오류 또는 빈 데이터로 표시될 수 있음 | 공통 JSON 응답 처리에서 로그인 만료, HTTP 오류, 형식 오류 안내 |
| 판매·외주·생산·포장·품질 일부 날짜 기본값이 UTC 기준 | 현지 달력 날짜를 쓰는 공통 함수로 변경. 날짜 범위도 같은 방식으로 표시 |

공통 응답 처리는 도면, 공정흐름도, FMEA(엑셀 포함), 관리계획서, 검사기준서, 판매 발주/발주 조회/출고 등록, 구매 발주/입고, 외주 발주/출고/입고에 적용합니다. 각 화면의 기존 fetch 옵션과 서버 권한 검사는 유지합니다. 공정흐름도의 행별 입력 오류 안내와 엑셀의 셀별 오류 안내도 유지합니다.

공통 파일은 `static/response_json.js`, `static/date_local.js`, `static/css/standard_document_ui.css`입니다. 변경한 외부 스크립트에는 캐시 버전을 변경했습니다.

## 유지한 업무별 차이

- 공정흐름도·FMEA·관리계획서는 문서 목록에서 선택합니다. 검사기준서는 검사구분·품번 선택 후 개정 이력을 조회하는 기존 흐름을 유지합니다.
- 원재료/외주 입고, 등록 공정, 완제품 등 조회 대상 제한과 관리계획서 공정 연결 조건은 유지합니다. 모든 품번을 일괄 노출하지 않습니다.
- 준비 중 기능을 새로 구현하거나 기존 발주·LOT·생산·재고 저장 규칙을 바꾸지 않습니다.
- 사용자가 반영하지 않기로 한 ‘검사항목명이 빈 행의 저장 차단’ 변경은 적용하지 않습니다. 현재는 빈 이름 행을 저장 대상에서 제외하는 기존 동작입니다.

## 정적 확인과 한계

- 서버 소스 130개를 Python AST로 읽어 문법 오류가 없는 것을 확인했습니다.
- 수정한 외부 JavaScript 14개와 변경·추가 HTML 24개를 대상으로 JS 문법/Jinja 템플릿 문법과 내부 스크립트 문법을 확인했습니다.
- 템플릿의 고정 `/static/` 파일 경로에 누락된 파일은 없었습니다.
- 일반 Python에는 Jinja2가 없어 첫 템플릿 문법 확인이 중단됐습니다. 저장소 `.venv/bin/python`에서 다시 확인했습니다.
- 이 결과는 기능 정상 동작이나 DB 저장 검증 결과가 아닙니다. 실행 테스트·브라우저·실제 DB 테스트는 하지 않았습니다.

모든 업무 화면을 같은 레이아웃으로 재작성한 작업은 아닙니다. 품번 조회의 팝업/행별 자동완성, 검사기준서의 문서 선택 흐름처럼 업무 구조가 다른 부분은 유지하며, 공통으로 사용할 조작과 표시 규칙을 먼저 맞췄습니다.
