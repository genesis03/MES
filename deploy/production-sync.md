# 생산실적 자동 동기화

관리자 메뉴의 **외부 연동 생산실적**에서 기존 UNI_MES 생산실적을 조회한다.
최초에는 올해 1월 1일부터 오늘까지 가져오고, 성공 완료 이후에는 기본 60분 간격으로 최근 7일을 다시 조회한다. 관리자가 화면에서 계정을 저장한 뒤 자동 동기화 사용을 켠다. 최초 조회가 중간에 실패하면 완료로 표시하지 않고 다음 실행에서 재시도한다.
서버가 실행 중일 때만 동작한다. 자동 조회와 수동 조회는 DB 실행 잠금으로 직렬화한다.

## 연동 계정

관리자 메뉴 → **외부 연동 생산실적** → **연동 계정 설정**에서 아이디와 비밀번호를 입력한다.
**로그인 확인**은 저장하지 않고 인증을 확인한다. **계정 저장**은 로그인 성공을 확인한 후 비밀번호를 암호화해 DB에 저장한다.
같은 아이디에서 비밀번호를 비우면 기존 비밀번호를 유지한다. 최초 저장과 아이디 변경에는 비밀번호가 필요하다.
계정 변경은 다음 동기화부터 서버 재시작 없이 적용되며 동기화 중에는 저장할 수 없다.

암호화 키는 서버의 문서 저장 폴더 상위 경로 `production-sync.key`에 저장한다. 환경변수 `PRODUCTION_SYNC_KEY_PATH`로 별도 경로를 지정할 수 있다.
DB만 다른 서버로 옮기면 암호화 키가 다르므로 해당 서버 화면에서 계정을 다시 저장한다. 키 파일은 별도로 보호·백업한다.
비밀번호와 인증 쿠키는 응답·화면·감사로그에 노출하지 않는다. 일반 계정은 페이지와 관련 API에 접근할 수 없다.

기존 서버 환경변수 `PRODUCTION_SYNC_USER`, `PRODUCTION_SYNC_PASSWORD` 방식도 유지하며, 화면에서 저장한 계정이 우선한다.
암호화 라이브러리 설치를 위해 변경된 `requirements.txt`를 적용하고 최초 한 번 MES 서버를 재시작한다.

## 화면 사용

1. 관리자 메뉴 → 외부 연동 생산실적에서 연동 계정을 저장한다.
2. 자동 동기화 사용, 조회 간격과 최근 조회 일수를 저장한다.
3. 최초 전체 조회가 완료됐는지 상태에서 확인한다. 추가 과거 데이터는 시작일·종료일을 지정하고 **선택 기간 지금 가져오기**를 사용한다(최대 366일).
4. 품번·LOT로 검색하고, 원본 공정명이 MES 공정명과 다르면 공정 연결에서 지정한다.
5. 동기화 이력에서 신규·수정·동일 건수와 실패 날짜 범위를 확인한다. 실패 후 같은 기간을 재조회할 수 있다.

## 데이터 처리 범위

- 외부 실적을 별도 테이블에 저장한다. 기존 MES 실적, 작업지시, 재고, BOM, 자재 차감과 생성 LOT는 변경하지 않는다.
- 품번은 내부 품목 마스터에 연결하고 품명은 마스터를 우선 표시한다. 쉼표 때문에 해석이 모호한 원본 품명은 자동 분할하지 않는다.
- 현재 중복 키는 LOT·작업번호·원본 공정명이다. 동일 키의 수량·시간 변경을 갱신한다. 원본 키 자체가 바뀌면 다른 실적으로 저장될 수 있으며, 키 변경·삭제 자동 반영은 지원하지 않는다.
- 작업수량 JOB_QTY는 양품, FAULT_QTY는 불량, F10은 셋업으로 연결한다. LOT_QTY는 전체수량으로 보관하고 양품+불량+셋업 합계를 비교한다. 차이가 있으면 확인사항을 표시한다.
- 자동 조회는 최근 기간만 다시 확인한다. 오래된 실적 수정은 수동 재조회가 필요하다.
- 날짜별 응답을 검증하고 날짜별로 저장한다. 중간 실패 시 완료된 날짜를 유지하며 이후 날짜는 저장하지 않는다.
- 원본에서 사라진 행은 자동 삭제하지 않는다. 실제 삭제와 조회 누락을 아직 구분할 수 없기 때문이다.
- 상대 시스템의 공식 외부 API가 아닌 확인된 화면 통신을 사용한다. 상대 화면 통신 변경에 영향을 받을 수 있다.
- 서버가 건수를 제공하면 수신 건수와 대조한다. 일별 조회로 범위를 줄였지만 페이지 처리와 전체 건수는 추가 확인이 필요하다.
- 신규 테이블은 기존 프로젝트 방식대로 다음 서버 시작 시 생성한다. 기존 테이블을 수정하거나 DB를 옮기는 작업은 수행하지 않는다.

## 서로 다른 품번과 사후 등록

MES에 없는 품번도 외부 실적 원본으로 보관한다. 나중에 품목을 등록하고 연결하면 기존에 가져온 실적에도 즉시 적용된다.
품번 연결은 **원본 품번 + 원본 공정 → MES 품목 ID**로 저장한다. 두 시스템의 품번 표기가 달라도 연결할 수 있으며, 원본 품번은 변경하지 않는다.
자동 연결은 원본 품번 또는 기본품번의 BOM을 따라 해당 공정의 생산품목을 찾는다. BOM의 하위 단계와 상위 완제품을 확인하며 순환 참조를 방지한다. 예를 들어 310061의 BOM에 310062-C가 있으면 조립 실적은 310062-C로 연결한다. 포장은 조립품의 상위 완제품을 찾는다. BOM이 없는 경우에만 같은 기본품번에 공정 접미사를 적용한다. 복합선반 -A, 탭핑 -B, 세레이션 -D, 은도금 -Ag, 조립 -C, 포장은 완제품이다. 연결한 MES 공정명을 우선하고 원본 공정명도 확인한다. 사용 중인 등록 품목이 하나일 때만 연결하고, 없거나 후보가 여러 개면 미연결로 표시한다. 알려지지 않은 공정은 동일 품번만 연결한다. 숫자 접미사 등 다른 품번 체계는 추측하지 않고 수동 선택한다.
품번 조회에서는 전체 사용 중인 MES 품목을 검색하고 BOM의 해당 공정 품목을 먼저 표시한다. 직접 지정한 연결이 자동 연결보다 우선한다. '자동 연결로 전환'은 수동 지정을 제거하고 현재 BOM과 공정별 규칙을 다시 적용한다. 생성 LOT나 재고를 변경하지 않는다.

## 현재 생산실적 양식과의 대응

일반 생산실적 현황에서 내부 등록 실적과 외부 연동 실적을 함께 조회한다. 외부 실적은 '외부 연동'으로 표시하며 삭제할 수 없다. 확인되지 않은 MES 작업지시나 작업자로 검색할 때는 외부 실적을 제외한다. 품번은 원본 및 연결된 MES 품번 모두 검색할 수 있고, 공정과 가공/조립 구분도 검색에 반영한다. 공정 연결에서 구분을 직접 지정하면 우선하며 복합선반·탭핑·세레이션은 가공, 조립은 조립으로 자동 구분한다.
목록과 합계의 명칭은 총생산수량으로 통일하며 양품 + 불량 + 셋업으로 계산한다. 외부의 원본 LOT수량은 별도로 보관해 합계와 비교한다. 셋업이 누락된 옛 자료는 총생산수량을 미확인으로 표시한다. LOT 차감·투입 LOT 열은 목록에서 제외하고 생성 LOT를 표시한다. 기존 자재 차감·재고 처리 방식은 유지한다.
외부 실적의 생성 LOT에는 수신한 원본 LOT를 표시한다. 생산호기는 원본 LOT의 끝에서 두 번째 자리 숫자로 표시한다(예: LX20261009065 → 6). 해당 자리가 숫자가 아니면 미확인으로 표시한다. 별도의 MES 생성 LOT나 재고를 생성하지 않는다. 작업자·주야·MES 작업지시는 확인되거나 연결되기 전까지 미확인/미연결로 표시한다. 수량이 확인되지 않은 항목을 숫자 0으로 대체하지 않는다.
양품·불량수량과 원본 보기의 LOT수량은 소수점 없이 정수로 표시한다. 원본 저장값은 유지한다. 작업수량·LOT수량·F10·원본 LOT와 작업번호는 원본 보기에서 확인한다.
F10은 셋업 수량으로 표시한다. LX20260325016의 F10=115가 사용자가 확인한 셋업=115와 일치했고, 원본 242행 모두 LOT_QTY=JOB_QTY+FAULT_QTY+F10 관계가 성립했다. 원본 값도 함께 유지한다.

### 출고이력 연동

외부 데이터 연동의 `출고이력` 대상을 선택해 기간별로 수집한다. 기존 공통 계정·접속키 자동 초기화·스케줄러·실행 잠금을 사용한다. 새 대상은 자동 활성화하지 않으며, 자동 동기화는 공통 설정에서 명시적으로 선택해 저장한다.

- 목록: `Common.Pop.OutDirect.OutDirectPopObj` / `SEARCH`, `OutDirectCondSet.OUT_DATE1/2`.
- 상세: `MES.Out.Mana.OutObj` / `Load`, 목록의 `RULE_NO`, `OUT_NUM`, `OUT_DATE` 사용. 상세 응답에 `Common.Set.LotSet`도 함께 반환된다.
- LOT의 `LOT_TR_NO` → `TradeDetailSet.RULE_NO`로 연결하고 품번, 거래 식별값, 수량도 검증한다. `LOT_NUM`은 원본 그대로 보존하며 `JOB_QTY`를 배정수량으로 사용한다.
- 전표는 `external_shipments`, LOT는 `external_shipment_lots`에 별도 저장한다. 동일 원본 전표는 갱신하고, 성공적으로 전체 조회한 날짜에서 사라진 전표는 비표시 상태로 보존한다. 자동 재조회는 알려진 과거 출고일도 포함한다.
- 내부 출고·수주·포장·재고 거래를 생성하거나 차감하지 않는다. 출고 내역 조회에서 내부·외부 구분, 외부 상세 LOT 확인이 가능하다. 외부 수정·삭제는 차단하고 원본 변경 후 재수집한다.
- 기존 출고 내역 및 LOT 계산/인쇄/엑셀에 같은 열·바코드 구조로 연결한다. 외부 전표 참조는 API에서 음수 ID, 내부는 양수 ID로 구분한다. 완료(`OUT_FIN`)·표시 중·전 행 LOT 배정수량 합계 일치 조건을 충족해야 출력한다. 실제 박스 수는 배정된 LOT 건수로 표시하며, MOQ 대비 환산값일 수 있는 원본 BOX_QTY의 정수 여부·LOT 건수 일치를 요구하지 않는다. 원본 BOX_QTY는 음수가 아닌 유한한 숫자로 검증하고 소수도 그대로 보관한다.
- 실제 수신 캡처의 3개 품번 / 20 LOT / 3,040개를 검증용 fixture로 사용한다. 인증정보는 fixture에 포함하지 않는다.
- 페이지 요청은 아직 관측되지 않았다. 서버 표시 건수 불일치 또는 목록이 25의 배수로 반환되면 페이지 제한 가능성을 오류로 알리고 해당 날짜를 저장하지 않는다. 전체 페이지를 확보한 것처럼 처리하지 않는다. 외부 접속 환경에서 첫 가져오기의 결과·건수는 운영자가 확인한다.

출고 수집 중 특정 전표의 검증에 실패해도 같은 날의 다른 전표와 이후 날짜를 계속 가져온다. 목록 조회 실패일은 그 날짜만 건너뛰며, 일부 전표에 실패한 날짜에서는 기존 전표를 원본에서 사라진 것으로 표시하지 않는다. 정상 전표는 저장하고, 일부만 처리된 실행은 `PARTIAL`(일부 오류)로 기록하며 최초 전체 수집 완료로 확정하지 않는다. 연동 이력의 오류 상세에는 날짜·출고번호·문제 필드·기준 건수·수신 건수를 표시한다. 인증정보나 원문 값은 진단에 포함하지 않는다. 품번·수량·식별값 등 필수 데이터의 불일치는 임의로 맞추어 저장하지 않는다. 외부 PRODUCT_NM은 수집·분리·검증 대상에서 제외한다. 출고 조회·출력 품명은 연결된 내부 품목마스터만 사용하며, 미연결 시 품명은 공란으로 두고 품번 미연결을 표시한다. 과거 수신분에 외부 품명이 남아 있어도 화면 품명 대체값으로 사용하지 않는다.

출고이력은 수동으로 미래 출고일도 선택할 수 있다(한 번에 최대 366일). 다른 대상과 함께 미래 기간을 지정하면 출고만 요청 종료일까지, 다른 대상은 오늘까지 실행하고 실제 기간을 접수 결과에 표시한다. 다른 대상만 선택한 미래 조회 제한은 유지한다. 자동 출고 수집은 한국시간 오늘을 기준으로 최근 조회 일수와 내일 하루를 포함하며, 최초 수집은 올해 1월 1일부터 내일까지이다. 연말에도 올해 기준 시작일을 유지한다. 출고 내역 조회 및 LOT 계산의 기본/초기화 종료일은 내일이며, 더 먼 미래일은 직접 지정할 수 있다. 공통 수동 가져오기 종료일은 출고 대상 선택 시 내일, 미선택 시 오늘로 자동 제안하되 사용자가 직접 지정한 종료일은 유지한다.
