# 서버 미사용 만료 및 남은 시간 표시

## 정책

- 관리자 20분, 일반계정 30분이라는 기존 미사용 기준을 서버 설정으로 옮깁니다. 기존 관리자 판정 함수를 재사용합니다.
- 환경변수 SESSION_ADMIN_IDLE_MINUTES / SESSION_USER_IDLE_MINUTES로 변경할 수 있습니다. 화면은 서버 응답값을 표시하므로 별도로 시간을 하드코딩하지 않습니다.
- 키보드 입력, 클릭/터치, 사용자 스크롤 조작 때만 활동 API를 호출합니다. 페이지 열기, 자동 조회, 상태 조회, 단순 마우스 이동은 미사용 시간을 초기화하지 않습니다.
- 전송은 최대 10초 간격으로 묶습니다. 마지막 입력의 서버 수신시각이 기준이므로 짧은 전송/네트워크 지연 차이가 있을 수 있습니다. 오래된 입력은 나중에 보내 세션을 되살리지 않습니다.
- 창을 닫는 것 자체는 로그아웃 또는 활동으로 처리하지 않습니다. 닫아 있는 동안에도 서버 만료시각이 지나면 해당 세션은 유효하지 않으며 재접속/업무 API 호출이 차단됩니다.
- 만료는 서버 요청 시 시각 비교로 판정합니다. 별도 스케줄러로 정확한 시각에 DB 행을 삭제할 필요가 없으며 만료 기록은 보존합니다.
- 같은 브라우저의 여러 탭은 같은 세션을 공유합니다. 다른 탭에서 실제 작업 중이라면 로그인은 유지됩니다. 다른 기기/브라우저 세션은 독립적으로 만료합니다.
- 네트워크 단절 시 화면에는 '로그아웃 시간 확인 불가'를 표시합니다. 브라우저가 만료시각을 임의로 연장하지 않습니다.

## 서버 인증

- auth_sessions 신규 테이블에 사용자 ID, 토큰 SHA-256 해시, 생성/마지막 활동/미사용 만료/절대 만료/폐기 시각을 저장합니다. 로그인 쿠키 원문은 저장하지 않습니다.
- 쿠키는 로그인마다 새로운 충분한 길이의 랜덤값을 사용하며 서버에서 매 요청에 만료/폐기 상태를 검사합니다.
- 기존 쿠키 보관 상한 7일을 유지하지만 서버 미사용 제한이 우선합니다. 활동하더라도 7일 절대 상한 이후에는 재로그인합니다.
- 로그아웃은 쿠키를 지우는 것 외에 서버 세션도 폐기합니다. 만료/폐기된 세션을 활동 API로 되살릴 수 없습니다.
- 활동 API는 상태 조회에서 받은 세션별 확인키와 동일 출처 검사를 사용합니다. READ 계정도 자신의 인증 활동은 갱신할 수 있지만 업무 쓰기 권한은 확대하지 않습니다.
- 새 전역 인증 검사로 개별 라우터가 인증 검사를 빠뜨려도 업무 화면은 로그인 화면으로, API는 401로 처리합니다. 로그인/로그아웃/정적 리소스 경로는 예외입니다.
- 기존 무기한 username|signature 쿠키는 인정하지 않습니다. 배포 후 기존 로그인은 한 번 해제되며 다시 로그인해야 합니다.
- 기존 SECRET_KEY/비밀번호 설정은 이번 변경으로 교체하지 않습니다. HTTPS 운영 환경에서 SESSION_COOKIE_SECURE=true 설정을 권장하며 HTTP/로컬에서는 기존 false를 유지합니다.
- 기술 세션 활동의 SQL 갱신은 업무 변경 이력을 대량 생성하지 않습니다. 기존 업무/LOT/문서 이력은 삭제하지 않습니다.

## 화면

- 사이드바 계정명 아래 '자동 로그아웃까지 19:59'처럼 남은 분:초를 항상 표시하며 매초 갱신합니다.
- 만료가 가까우면 기존 주의 색상과 저장 안내를 표시합니다. 서버 만료/활동 갱신 기준은 변경하지 않습니다.
- 표시와 서버 만료는 동일한 서버 응답을 사용하며 상태 조회 자체는 만료를 연장하지 않습니다.
- 절전/탭 재열기 시 서버 상태를 다시 확인합니다. 만료 상태이면 로그인 화면으로 이동합니다.

## 적용 및 사용자 확인

1. 실제 DB와 도면 저장소를 백업한 뒤 사용자가 main을 git pull하고 서버를 재시작합니다.
2. 기존 create_all 과정에서 auth_sessions 테이블만 추가합니다. 기존 사용자/LOT/문서 데이터를 재작성하거나 DB 파일을 교체하지 않습니다.
3. 다시 로그인한 뒤 계정 아래 남은 시간 표시, 실제 조작 시 갱신, 자동 조회만 있을 때 감소를 확인합니다.
4. 동일 브라우저의 MES 탭을 모두 닫고 해당 미사용 제한보다 오래 지난 뒤 다시 접속하여 재로그인을 요구하는지 확인합니다.
5. 로그아웃 뒤 다른 탭에서도 기존 세션이 차단되는지 확인합니다. 다른 탭에서 계속 작업 중인 경우에는 공유 세션 시간이 갱신될 수 있습니다.
6. Oracle 일괄 배포는 로컬 확인 뒤 진행합니다. /home/ubuntu/MES/data/manual_labels.db와 도면 원본을 백업하고 운영 DB 경로를 유지합니다. GitHub의 DB로 덮어쓰지 않습니다.

- 요청에 따라 이 변경의 실행 테스트/브라우저 확인은 수행하지 않았습니다. 소스 검토만 했으며 실제 동작 확인은 사용자가 수행합니다.
